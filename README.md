## AWS and cloud architecture

I define and document cloud architectures on AWS, not just deploy to them:

- **Architecture definition**: I turn requirements into service layouts, diagrams and written decisions that a team can build from.
- **IAM**: roles, policies and trust relationships designed for least privilege, with separate roles per service and per environment.
- **S3**: bucket design for storage and integration, including bucket policies, access control, encryption and lifecycle rules.
- **Containers**: backend services packaged with Docker and run on Kubernetes, on AWS and GCP.

## How I build with AI agents

- **Spec-Driven Development (SDD)**: the spec is the source of truth. I write the requirements and acceptance criteria first, and agents implement against them.
- **Test-Driven Development (TDD)**: failing tests come before code, so every agent has an objective definition of done.
- **Sub-agents**: work is split into independent tasks that run in parallel, each in an isolated context and its own git worktree.
- **Council patterns**: several agents or models review the same design or diff independently, and a final pass reconciles their findings before I decide.
- **Claude Code and Codex**: my daily tools for implementation, review, refactoring and debugging, with a human in the loop on every merge.
